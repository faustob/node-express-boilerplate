**Self-review:** 2 generation passes — ⚠ passed with warnings.
**Auto-fixed during review (3):**
- qr-unwired-telemetry (`src/index.js`): httpMetricsMiddleware is registered with app.use() only after MongoDB connects, and it is appended AFTER all routes were already mounted in ./app (app.use(router) happens at require time). Express runs middleware in registration order, so this middleware sits behind the router's route handlers and its res.on('finish') never fires for matched routes — the HTTP latency and availability SLIs are not measured for actual API requests.
- qr-not-a-noop (`src/config/tracing.js`): The metric instruments (httpServerRequestDuration, httpServerRequestOutcomes, httpServerActiveRequests, authOperations) are created at module load via metrics.getMeter() immediately after sdk.start(). If sdk.start() throws and is swallowed by the try/catch (no metrics provider registered), metrics.getMeter() returns a NoopMeter whose instruments never rebind, silently dropping all SLI metrics.
- qr-preserves-behavior (`src/config/tracing.js`): Wrapping sdk.start() in a try/catch that swallows the error and only logs a warning changes error handling: a genuine SDK startup failure is now silently ignored rather than surfacing, and the comment's assumption (an already-registered agent) does not match this app-sdk model where this diff is the sole registrant.
**Outstanding (1):**
- ⚠ qr-metric-naming (`src/config/tracing.js`:47): The new counter name 'http.server.request.outcomes' uses a plural noun for a plain count and does not follow semconv (semconv distinguishes outcomes via attributes, not a metric named 'outcomes'). A count metric should be singular/unsuffixed like 'http.server.request.count' or rely on the semconv histogram's count. — _Rename to a count-shaped semconv-aligned name and carry outcome via the existing attributes rather than encoding it in the metric name._
