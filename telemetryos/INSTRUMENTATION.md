**Auto-fixed during review (3):**
- qr-unwired-telemetry (`src/index.js`): `app.use(metricsMiddleware)` is appended to the Express stack inside the `mongoose.connect().then()` callback, i.e. after `src/app.js` has already mounted the router and the 404/error handlers. Express executes middleware in registration order, so a matched route sends its response and never calls `next()` into this last-registered middleware — the duration/outcome/in-flight instruments are never reached and both HTTP availability and P95 latency SLIs emit nothing.
- qr-export-pipeline (`src/config/tracing.js`): The NodeSDK now owns a PeriodicExportingMetricReader (default ~60s export interval) but nothing ever calls `sdk.shutdown()`; `src/index.js` exits via `process.exit(1)` in exitHandler and only calls `server.close()` on SIGTERM, so the last interval of metrics and any batched spans are dropped on every restart/deploy.
- qr-metric-naming (`src/config/tracing.js`): The new counter `auth.operations.total` carries a `.total` suffix while the other new counters introduced in the same diff (`http.server.request.outcomes`) are unsuffixed, mixing two conventions for plain counts; semconv style leaves counters unsuffixed.
