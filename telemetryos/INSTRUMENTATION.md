- general (`src/config/tracing.js`): The `http.server.request.duration` histogram records values in SECONDS but is created with no `advice.explicitBucketBoundaries`, so it uses the OTel default boundaries ([0, 5, 10, 25, 50, ... 10000]) which are sized for milliseconds. Every sub-second request lands in the first bucket, making the P95 latency SLI (< 200ms) uncomputable from the exported histogram.
- general (`src/app.js`): `httpMetricsMiddleware` is mounted after `authLimiter` and the body parsers, so requests rejected earlier in the chain (429 from the auth rate limiter, 400 from `express.json()` parse failures) never install the `res.on('finish')` hook and are excluded from both the availability counter and the latency histogram.
- qr-unwired-telemetry (`src/index.js`): `app.use(httpMetricsMiddleware)` is attached in src/index.js AFTER `require('./app')` has already mounted all routers, the 404 handler and the error handlers, so the middleware sits at the very end of the Express stack and is never reached for any request that a route (or the error handler) answers. Both the availability counter and the p95 duration histogram therefore never record anything.
- qr-export-pipeline (`src/config/tracing.js`): The new PeriodicExportingMetricReader is never flushed or shut down: src/index.js's exitHandler/SIGTERM paths call process.exit(1)/server.close() without awaiting sdk.shutdown(), so metric points accumulated since the last periodic export are lost on every shutdown.
